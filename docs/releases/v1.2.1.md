## SnakeyOS 1.2.1: more ARM64 hardware

| File | For |
|---|---|
| **`SnakeyOSx86.iso`** | 64-bit PCs (x86_64), BIOS or UEFI |
| **`SnakeyOSARM64.iso`** | 64-bit ARM machines with UEFI: QEMU `virt`, ARM servers, Raspberry Pi 4/5 with [UEFI firmware](https://github.com/pftf), development boards with UEFI |

### What is new

- **GICv3 interrupt controller (and GICv4).** Most ARM servers, many modern boards and QEMU's `virt` with `gic-version=3` use it. GICv2 still works. Version 1.2.0 needed a GICv2.
- **Firmware that starts at EL2 (hypervisor mode)** now works with either GIC. Many real boards and servers start this way.
- Tested in QEMU, all reaching the desktop with keyboard, mouse and network:
  - **CPUs:** Cortex-A53 (as in the Raspberry Pi 3), Cortex-A72 (as in the Raspberry Pi 4) and `max` (the newest ARMv8/v9 QEMU emulates).
  - **Machine setups:** GICv2 and GICv3, each with firmware starting at EL1 and at EL2.

### Try the ARM64 version

```bash
# Debian/Ubuntu: sudo apt install qemu-system-arm qemu-efi-aarch64
cp /usr/share/AAVMF/AAVMF_VARS.fd vars.fd
qemu-system-aarch64 -M virt -cpu max -m 1024 \
  -drive if=pflash,format=raw,readonly=on,file=/usr/share/AAVMF/AAVMF_CODE.fd \
  -drive if=pflash,format=raw,file=vars.fd \
  -device ramfb -device qemu-xhci -device usb-kbd -device usb-tablet \
  -drive file=SnakeyOSARM64.iso,media=cdrom,if=none,id=cd,readonly=on \
  -device virtio-scsi-pci -device scsi-cd,drive=cd -nic user,model=virtio-net-pci
```

### Limits, honestly

- **ARM64 has been tested in QEMU, not yet on physical boards.** It needs UEFI firmware with ACPI and a linear framebuffer.
- **PyWin does not run on ARM64.** It runs Windows x86-64 programs, which need an x86 processor.
- **Arduino and other microcontrollers cannot run SnakeyOS.** They have kilobytes of RAM, and SnakeyOS needs about 512 MB.
